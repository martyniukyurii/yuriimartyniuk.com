# Telegram-бот для блогу

Бот працює як webhook у тому самому Next.js-проєкті на Vercel. Постійний процес, MTProto-сесія, парсер каналу і cron не потрібні.

## Налаштування

1. Створи бота через BotFather і додай його адміністратором свого каналу з правом публікувати.
2. У Vercel → Environment Variables додай значення з `.env.example`: `MONGODB_URI`, `SITE_URL`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_OWNER_ID`, `TELEGRAM_CHANNEL_ID`, `TELEGRAM_WEBHOOK_SECRET`.
3. `TELEGRAM_OWNER_ID` — твій числовий Telegram ID. Бот приймає команди лише від цього користувача в приватному чаті.
4. `TELEGRAM_CHANNEL_ID` — `@username` публічного каналу або числовий `-100…` ID приватного каналу.
5. `SITE_URL` — точний HTTPS origin production-деплою, наприклад `https://www.yuriimartyniuk.com`. Без шляху, query чи hash.
6. `TELEGRAM_WEBHOOK_SECRET` — випадкові 32–256 символів: латинські літери, цифри, `_` або `-`. Не використовуй токен бота як цей секрет.
7. Розгорни сайт. Додай ті самі значення локально в `.env.local` (файл ігнорується Git).
8. Один раз виконай `node scripts/setup-telegram-bot.mjs`. Скрипт налаштує три команди, webhook і перевірить його URL. Токен та секрет не виводяться.

Реєстрація навмисно задає `max_connections: 1`: вкладення одного типу отримують номери в порядку надходження. Не змінюй це без переробки нумерації. Бот використовує новий `sendRichMessage`; потрібні актуальні Telegram-клієнти для перегляду розширеної розмітки.

## Щоденна робота

- `/template` — бот надсилає промпт для LLM та приклади тегів одним звичайним повідомленням.
- `/new` — створює нову чернетку.
- Надішли HTML звичайним повідомленням. Довгу статтю можна надсилати частинами: перша містить `<h1>`, наступні додаються до тексту. Нове повідомлення з `<h1>` замінює текст. Загальний ліміт — 32000 символів.
- Надішли фото, альбоми, відео, аудіо, документи. Бот підтверджує кожен файл та називає його `photo-1`, `video-1`, `audio-1`, `file-1` тощо. Числа окремі для кожного типу. Користуйся підтвердженими назвами, а не порядком візуального відображення альбому.
- `<gallery refs="photo-1,photo-2"/>` вставляє альбом у цьому місці; `<img ref="photo-1"/>` вставляє окрему картинку.
- Дочекайся підтвердження всіх файлів і виконай `/publish`. Бот перевірить розмітку та всі ref, збере статтю на сайті й rich message у каналі.
- Доступні заголовки, списки, таблиці, курсив, жирний текст, цитати, код, спойлери, розгортувані блоки, галереї, фото/відео/аудіо/файли. Повний підтримуваний набір — у `public/blog-template.txt`. Кнопки Telegram, геокарти, формули та довільний HTML не входять до першої версії.
- `<tags>` і `<excerpt>` — службові теги бота, вони не публікуються в тілі статті. Один `<h1>` задає назву. Не вставляй медіа всередину абзаців чи клітинок таблиць.

У шаблоні наведено приклади, а не готову статтю: LLM має прибрати зайві теги та вкладення. Файли `.html/.txt` завжди сприймаються як текст статті; щоб додати їх як завантажуваний файл, запакуй у ZIP.

## Медіа без власного сховища

MongoDB зберігає лише метадані та Telegram `file_id`. Нові файли не записуються у GridFS або файлове сховище. `/api/media/<opaque-id>` знаходить файл тільки серед опублікованих постів, викликає `getFile` і передає відповідь Telegram потоком. Токен ніколи не віддається у браузер або redirect. Шлях завантаження отримується знову після закінчення кешу.

Обмеження: стандартний хмарний Bot API завантажує файли до 20 МБ. Бот відхиляє більші вкладення до публікації. Великі відео потребують зменшення, зовнішнього сховища або окремого Local Bot API server, який не запускається як коротка функція Vercel. Range-запит передається upstream; підтримка перемотування залежить від відповіді Telegram. Потік витрачає трафік і час функції Vercel. Це не SLA для медіа-CDN; зміну бота/токена чи доступності Telegram треба враховувати. Сторонні сервіси з вимогою передати їм токен не використовуються.

Старі GridFS-файли залишені доступними. Парсер каналу і `/api/sync-telegram` прибрані; старі повідомлення автоматично не імпортуються.

## Часткова публікація та відновлення

HTML можна надсилати повідомленнями з телефона. Перша частина містить `<h1>`, наступні додаються до тексту. Нове повідомлення з `<h1>` замінює текст статті. Загальний ліміт — 32000 символів.

Чернетки, отримані update_id та статуси публікації зберігаються в MongoDB, а не в пам’яті функції. Повтор webhook або `/publish` не створює другий пост на сайті. Явна відмова Bot API залишає канал у `pending`: виправ права / розмітку і повтори `/publish`. Перед цим `/new` заблоковано, щоб не загубити незавершену доставку.

Відправка у два незалежні сервіси не є атомарною. Якщо Telegram прийняв пост, але відповідь або запис у MongoDB загубилися, неможливо гарантувати exactly-once через Bot API. Статус `sending`/`uncertain` тому не перевідправляється автоматично.

Після перевірки каналу вручну у MongoDB знайди поточну чернетку через `bot_state.draftId`:

- Пост є в каналі: встанови `bot_drafts.channelState = "sent"`, `channelMessageId` та `locked = false`.
- Поста немає: встанови `channelState = "pending"`, `locked = false`; повтори `/publish`.
- Якщо функцію перервали до звернення в Telegram і `locked` залишився `true`, після перевірки стану встанови `locked = false`.

Не очищай `sending`/`uncertain` без перевірки каналу. Після успішної публікації в обидва місця текст зафіксований. Якщо канал явно відхилив пост (`pending`), можна надіслати виправлений HTML і повторити `/publish`: сайт оновиться, канал буде відправлено повторно; редагування опублікованих статей і додаткові джерела (Facebook/Instagram) — окрема функціональність.

## Перевірка

`npm run test:blog` — перевірка розмітки, безпеки, refs і сценарію публікації з підставними MongoDB/Telegram.
`npx tsc --noEmit` — типи.
`npm run build` — production-збірка.

Реальні webhook, MongoDB, права каналу, rich messages і медіапотоки слід перевірити на тестовому каналі після налаштування секретів. Ці налаштування не входять у репозиторій.

Офіційна документація: https://core.telegram.org/bots/api#sendrichmessage та https://core.telegram.org/bots/api#getfile.

## Керування статтями

`/posts` показує опубліковані через бота статті з кнопками «Редагувати» та «Видалити». Редагування: скопіюй поточний HTML із повідомлень бота, надішли оновлений HTML із `<h1>` та `/publish`. Зберігаються slug, вкладення та ID повідомлення в каналі. Видалення потребує окремого підтвердження, чинного 10 хвилин. Стаття приховується на сайті й отримує tombstone, який запобігає повторній публікації. Якщо Telegram відмовляє видаляти повідомлення (зокрема після 48 годин), бот повідомляє, що його треба перевірити / видалити вручну. Старі статті попереднього парсера не входять у список бота.
